# 烟火账

烟火账是一款本地优先的个人 Android 记账应用，面向 Android 12–16，主要验收设备为 Android 16、HyperOS 3、机型代码 `2509FPN0BC`。当前版本 **2.6.0**（versionCode 25）。

账单、分类、规则和统计都保存在本机；只有启用 DeepSeek 后，自动分类、消费月报和截图记账才会联网（详见[隐私边界](#隐私边界)）。

## 主要功能

### 微信自动记账

- 识别微信系统通知中明确的“已支付￥金额”模板，立即生成支出；
- 通过无障碍服务读取微信支付成功页的金额和交易对象，兼容微信 Lite 把文字放在 `contentDescription` 里的页面；服务连接或恢复后会主动检查当前页面，避免静态成功页漏采；
- 成功页的文字里读不到交易对象时，对该页截图一次，用随 APK 打包的 ML Kit 中文模型在本机识别商家名，并与金额交叉校验；识别失败时不猜测，按“商家待确认”处理；
- 无障碍服务连接后转为前台服务（低优先级静默通知），防止 HyperOS 在微信启动时冻结本应用，导致支付页事件延迟送达而漏读；
- 发送微信红包时暂存金额，返回聊天页并检测到新增的己方红包卡片后生成待确认事件；
- 微信支付结果短信可单独生成支出，也可补全已有的通知账单；普通银行短信只生成待确认事件；
- 同一来源的事件重复到达不会重复记账，不同来源的同一笔交易会合并，同金额无法区分时进入待确认。

### 截图记账（2.6.0 新增）

- 支付宝、抖音、美团、校园食堂等不会自动记账的支付，可以在记账表单里点“从截图识别”选图，或在相册、截图预览里通过系统分享发到“截图记账”；
- 截图直接发给 DeepSeek Flash 视觉模型识别，固定开启思考模式、不限制输出长度，不跟随设置里的模型和思考选项（V4 Pro 不支持图片）；
- 提示词只按含义描述字段，不针对任何 App 写死版面，换一种支付截图不需要改代码；
- 识别出的金额、收支类型、时间、交易对象、支付方式、商品摘要和建议分类只回填表单，核对后保存才入账；
- 图上没写明交易对象时允许推测并标注“推测”和依据，推测的对象默认不生成个人规则；找不到时间时使用当前时间并提示核对；
- 支付宝、抖音等记为“其他”支付方式，平台名写进备注；分类按个人规则、本地关键词、模型建议的顺序选取；
- 已有金额和方向相同、时间相近的账单时提示“可能已经记过这笔”（不区分支付渠道，只提示不拦截）。

### 手动记账与账单管理

- 底部五等分导航，中间加号可从任意页面打开“记录一笔”；
- 新增、编辑、软删除和恢复账单，删除自动账单后保留忽略指纹，避免同一事件重新导入；
- 待确认页处理转账、退款、红包、模板未知和同金额歧义等事件，处理前不计入统计；
- 转账可选择转入或转出以及是否计入普通收支；退款可冲减退款当月，也可关联原消费并调整原消费月份。

### 分类与规则

- 自动分类依次使用个人对象规则、本地高可信关键词、DeepSeek；DeepSeek 只能从已有分类中选择；
- DeepSeek 无法判断、未配置、网络异常或额度不足时保持“未分类”并发通知提醒手动分类；
- 手动分类时可记住标准化后的交易对象，并同步整理历史相同对象的未分类账单；
- 自定义分类的名称、emoji 图标、颜色、排序和启用状态，管理个人规则。

### 统计与消费月报

- 首页概览、本月统计、分类排行、连续圆环图和对齐的六个月收支双柱图；
- 独立的月度分析页可按月份查看本地计算的净支出、最大单笔、商家消费金额和频率 TOP 10、高频小额候选和本地异常候选；
- 启用 DeepSeek 后生成结构化消费月报（关键发现、分类与行为洞察、日常支出判断、可优化金额、下月建议、数据限制等）；每月最后一天 23:30 自动生成，也可随时手动生成或重试。

### 提醒、安全与备份

- 首次启动引导开启通知访问、无障碍服务、短信、通知权限和 HyperOS 自启动/电池设置，并持续检查权限状态；
- 每日待确认汇总提醒，时间可设置；
- 生物识别或设备凭据应用锁，可设置离开应用多久后锁定；
- AES-256-GCM 密码加密备份与事务性恢复，备份包含 DeepSeek API Key；
- 参考 Cashew 的绿色种子色主题、柔和背景、大圆角面板、紧凑账单行和深色模式。

### DeepSeek 设置

在“设置 → DeepSeek 分类与月度分析”中启用并填写 API Key，可为自动分类和月报选择 V4.1 Flash 或 V4 Pro，以及思考或非思考模式。截图记账使用同一个 API Key，但模型和思考模式固定（见上文）。

## 工程环境

- JDK 17
- Android SDK Platform 36
- Android Build Tools 36.0.0
- Gradle Wrapper 8.11.1
- Kotlin 2.1.20 / Android Gradle Plugin 8.9.2 / KSP 2.1.20-1.0.32
- 主要依赖：Jetpack Compose（BOM 2025.05.01）、Room 2.7.1、WorkManager、DataStore、kotlinx.serialization、ML Kit 中文文字识别（bundled 版）

构建前请设置 JDK 和 Android SDK 环境变量，`build.ps1` 会检查配置并调用项目自带的 Gradle Wrapper：

```powershell
$env:JAVA_HOME="C:\path\to\jdk-17"
$env:ANDROID_SDK_ROOT="C:\path\to\android-sdk"
.\build.ps1 testDebugUnitTest lintDebug assembleDebug
```

- `build.ps1` 是不带 BOM 的 UTF-8 文件并含中文，Windows PowerShell 5.1 会按系统代码页解析而报错，请用 PowerShell 7 运行，或直接设置同样的环境变量后调用 `gradlew.bat`；
- APK 只打包 `arm64-v8a` 原生库（ML Kit 每个 ABI 各带一份，可省约 28MB），32 位手机和不带 ARM 转译的 x86 模拟器无法安装；
- Debug 包的包名带 `.debug` 后缀，可以和正式版同时安装，数据互不相通。

## 正式签名

Release 构建从环境变量读取签名信息，不在源码中保存密钥：

```powershell
$env:YANHUO_STORE_FILE="C:\secure\yanhuozhang-release.jks"
$env:YANHUO_STORE_PASSWORD="密钥库密码"
$env:YANHUO_KEY_ALIAS="yanhuozhang"
$env:YANHUO_KEY_PASSWORD="密钥密码"
.\build.ps1 assembleRelease
```

后续覆盖安装必须复用同一签名密钥。密钥丢失后只能卸载重装，卸载会删除本机数据。

## 代码结构

- `core/`：金额解析、微信通知/短信/支付页/红包模板解析、来源指纹、跨来源匹配、本地关键词分类和统计计算；
- `classification/`：本地规则之后的 DeepSeek 结构化分类与失败回退；
- `analysis/`：月度消费快照、本地月度分析、月报提示词与 DeepSeek 月报解析；
- `recognition/`：截图记账的图片预处理、DeepSeek 视觉识别、结果校验、查重提示和分享收件箱；
- `data/`：Room 表、索引、迁移、DAO、事务仓库和个人规则；
- `settings/`：DataStore 设置（DeepSeek、截图识别、提醒、应用锁等）；
- `system/`：通知监听、短信接收、微信支付页无障碍服务与前台服务、支付页截图 OCR、提醒与月报定时任务、HyperOS 设置跳转；
- `backup/`：版本化备份、认证加密和恢复校验；
- `ui/`：Compose 页面、统一账单编辑器、月度分析页和 ViewModel。

## 隐私边界

- 只有启用 DeepSeek 且本地规则无法分类时，才会发送当前账单的交易对象、备注、金额、收支方向、支付渠道和候选分类；
- 启用 DeepSeek 后，月报会发送目标月全部消费与退款的时间、金额、商家、分类、支付方式和备注；不会发送收入、转账、数据库内部 ID、原始通知或短信；
- 截图记账只在启用 DeepSeek 后、你主动选择或分享某张截图时，才把这张截图（含图上订单号等全部可见内容）连同当前时间和分类名发送给 DeepSeek；总像素超过约 1300×1300 时先在本机等比缩小，带 GPS 位置的照片会重新编码去掉位置信息；分享来的截图只临时复制到应用缓存，识别后即删除；
- DeepSeek API Key 保存在应用本地设置中，并随密码加密备份保存；
- 无障碍服务仅订阅微信包名，最多读取 200 个可见文字节点；
- 支付成功页的商家名截图识别（与截图记账无关）只在本机用 ML Kit 完成，截图不上传、默认不落盘，可在设置中关闭；ML Kit SDK 可能向 Google 发送匿名的使用和性能统计；
- 支付页截图识别的调试模式默认关闭，开启后截图和识别日志只保存在应用专属目录（`Android/data/<包名>/files/merchant-ocr`），可在设置中一键清除；
- 只申请 `RECEIVE_SMS`，不申请 `READ_SMS`，不会扫描历史短信；
- 原始通知和短信文本仅保存在应用私有数据库；
- 自动生成的普通支出静默入账，异常、待确认或待手动分类时才发通知；
- 导出的备份文件必须使用密码解密，密码无法找回。

## 当前限制

- 微信通知只识别“已支付￥金额”这类明确模板，微信短信只覆盖已有真实样例的支付结果短信；银行短信没有真实样例，只做待确认候选；
- 微信通知没有商户信息时，本地关键词通常无法分类；DeepSeek 仍无法判断则保持“未分类”；
- 微信未向无障碍框架公开文字且截图识别也失败（安全窗口黑屏、金额校验不一致或找不到商家）时，按“商家待确认”处理；
- 微信红包需要从金额页连续经过发送操作返回聊天页；应用未同时观察到金额和新增己方红包卡片时不会生成事件；
- 支付宝、抖音等平台没有自动记账，只能通过截图记账补录；截图记账一次只识别一笔交易，账单列表截图需打开单笔详情页再截图，超长滚动截图缩小后小字可能看不清；
- 云同步、资产账户和预算不属于当前版本；
- 应用无法早于微信或运营商产生系统通知/短信。
